# 钉钉上线就绪说明 · `dingtalk-ready` 分支

> 本分支(`dingtalk-ready`)完成钉钉 H5 应用上线的代码侧准备,不依赖任何外部资源即可合并到 `main`。
> 上线日由运维填入钉钉密钥与域名即可工作。

---

## 一、本分支做了什么

### 1. 后端(`server/app.py`)
- 启动时若 `SESSION_SECRET` 未设置,自动生成并**回写 `server/.env`**,保证重启后会话不掉
- 关闭 `app.run(debug=True)` 硬编码,改由 `DEBUG=true/false` 环境变量控制(默认 `false`)
- `CORS` 改为白名单模式,通过 `CORS_ORIGINS=` 配置;`DEBUG=true` 时自动放开
- 全局 `MAX_CONTENT_LENGTH = 30 MB`(可通过 `MAX_UPLOAD_MB` 调整),413 错误统一返回
- 上传接口加 in-memory 频率限制(默认 5 次/分钟/身份;可通过 `UPLOAD_RATE_PER_MIN` 调整)
- 新增 `GET /api/health`:返回数据库 / AI / 钉钉 / 模式状态,可作 Nginx upstream 探针 + 钉钉应用探针
- `POST /api/auth/dingtalk` 成功后**自动 upsert `user_bindings`**(新用户默认 `parent`;命中 `DINGTALK_DEFAULT_ADMINS` 的 unionId 自动 `admin`)
- 全套日志(access / error)落地 `logs/` 目录,按日 rotate(access 14 天,error 30 天)

### 2. 前端钉钉接入(`assets/dingtalk-bootstrap.js`)
完整重写:
- `dd.ready` 后拉 `authCode` → POST `/api/auth/dingtalk` → 存 `sessionToken`,**3 次自动重试**
- 全局劫持 `fetch`,对所有 `/api/*` 请求**自动注入 `Authorization: Bearer <token>`**(同时受益于普通浏览器测试)
- 自动同步页面 `<title>` 到钉钉顶栏(`dd.biz.navigation.setTitle`)
- 钉钉 webview 内自动加 `.in-dingtalk` body class,自定义返回按钮自动隐藏(避免与钉钉顶栏重复)
- 失败时弹**友好提示页**(全屏遮罩 + 重试按钮),不再静默 `console.warn`
- 注入 H5 兼容补丁 CSS:`text-size-adjust:100%`、`overscroll-behavior-y:contain`、`touch-action:pan-x pan-y`、iOS 安全区

### 3. 前端身份层(`assets/user-auth.js`)
- 在钉钉 webview 内**强制等待** `bs:logged-in` 事件(最长 8s),不允许 demo 旁路
- 拿到 sessionToken 后调 `/api/auth/me` 取得真实角色/绑定关系
- 8s 超时退回 demo 模式 + 控制台 warning,避免完全卡死

### 4. 8 个 HTML 页面接入 JSAPI
`login.html`、`island-homepage.html`、`island-archive.html`、`island-health.html`、`island-reading.html`、`island-activity.html`、`island-award.html`、`island-art.html`

均在 `user-auth.js` 之前注入:
```html
<script>window.BS_DINGTALK_CORP_ID = '__INJECT_CORP_ID__';</script>
<script src="https://g.alicdn.com/dingding/dingtalk-jsapi/2.13.42/dingtalk.open.js"></script>
<script src="assets/dingtalk-bootstrap.js"></script>
```

### 5. 环境变量样板(`server/.env.example`)
新增字段:`DEBUG / CORS_ORIGINS / MAX_UPLOAD_MB / UPLOAD_RATE_PER_MIN / LOG_DIR / PORT / DINGTALK_DEFAULT_ADMINS / OSS_*(预留)`

## 二、上线日运维要做的 3 件事

### 1. 替换 corpId 占位符
8 个 HTML 中的 `__INJECT_CORP_ID__` 需要替换为真实 corpId。**推荐 Nginx 做**(不动代码):
```nginx
location ~ \.html$ {
    sub_filter '__INJECT_CORP_ID__' 'dingxxxxxxxxxxxxx';
    sub_filter_once off;
    sub_filter_types text/html;
}
```
或者部署脚本里 `sed -i 's/__INJECT_CORP_ID__/真实corpId/g' *.html`。

### 2. 填写钉钉密钥 + 默认管理员
编辑生产服务器上的 `server/.env`:
```bash
DINGTALK_AGENT_ID=...
DINGTALK_APP_KEY=...
DINGTALK_APP_SECRET=...
DINGTALK_CORP_ID=...
DINGTALK_DEFAULT_ADMINS=ding-union-id-1,ding-union-id-2
DEBUG=
CORS_ORIGINS=https://baoshan.your-domain.com
```

### 3. 用 gunicorn 启动
```bash
pip3 install gunicorn
cd /opt/baoshan
gunicorn -w 4 -k gthread -b 127.0.0.1:5050 \
  --access-logfile - --error-logfile - \
  --chdir server app:app
```
(systemd 配置见 `server/baoshan.service`)

```

返回:
{
  "status": "ok",
  "db": true,
  "ai_configured": true,
  "dingtalk_configured": true,
  "mode": "prod",
```

- gunicorn worker 数:**试点期固定 `-w 1`**(保证 rate limit 准确);全量上线接 Redis 后再 `-w 4`
- 生产 `.env` 必填:`DEBUG=`(空) + `DISABLE_DEMO=true`(关闭 `?role=` 旁路)
- 隐私数据(学生真实姓名截图、外校公示材料 doc)**不入 git**(见 `.gitignore` 的"学生真实数据"段)
