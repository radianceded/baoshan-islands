## 4. `ab_menus` 表（1893 行）的合并问题

旧 excel 导入了 **20 周 × 5 天 × A/B × 多道菜** ≈ 1893 行。每行一道菜：
```
id, week_number, menu_date, meal_set (A/B), category, dish_name, ingredient, calories, ...
```

我们现在的 `weekly_menus` 表是**每周一张图**：
```
id, week_number, parity, date_start, date_end, image_path
```

两者**目的不一样**：
- `ab_menus` = 文字菜品明细（家长选餐时显示具体吃什么）
- `weekly_menus` = 总务老师上传的菜单**图片**（家长看图）

建议：**两个都保留**，但要在前端：
- 家长选餐界面：先显示 `weekly_menus.image_path`（图片优先）
- 没有图片时回退到 `ab_menus` 拉文字菜品

后端可加：`GET /api/menus/dishes?week=N&parity=odd` ← 从 `ab_menus` 聚合返回 A/B 餐每天的菜品列表。

## 7. 数据库一键导出 / 检视命令

```bash
# 查所有表 + 行数
python3 -c "import sqlite3; c=sqlite3.connect('student_data.db'); \
[print(f'{t[0]:20s} {c.execute(f\"SELECT COUNT(*) FROM {t[0]}\").fetchone()[0]} 行') \
for t in c.execute(\"SELECT name FROM sqlite_master WHERE type='table' ORDER BY name\")]"

# 看某张表的 schema
sqlite3 student_data.db ".schema students"

# 看某张表的前 5 行
sqlite3 student_data.db "SELECT * FROM accounts LIMIT 5"

# 完整 dump
sqlite3 student_data.db .dump > backup.sql
```

## 8. 最终目标的表结构（DB 完全够用后的样子）

```
accounts          ← 登录 + 角色 + 绑定
   │
   ├─ bound_id_card → students.id_card
   │
students          ← 学生主表
   ├─ fitness_tests       (1:N 体测)
   ├─ vision_tests        (1:N 屈光)
   ├─ allergies           (1:N 过敏)
   ├─ awards              (1:N 旧奖项 by name)
   ├─ award_certs         (1:N 班级证书)
   ├─ clubs               (1:N 社团报名 by name)
   ├─ borrows             (1:N 借阅 by id_card) ← 待建
   ├─ meal_choices        (1:N 选餐 by id_card)
   └─ custom_students     (家长 demo 用)

books             ← 阅读岛 ← 待建
weekly_menus      ← 总务上传图片
ab_menus          ← 旧 excel 菜品明细
```

完全 DB 化后，**前端不存在任何 mock 数据**，纯展示层 + AI 调用。
