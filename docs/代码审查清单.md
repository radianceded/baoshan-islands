# 代码审查清单 (Code Review Checklist)

## 提交前自检清单

### 功能性检查
- [ ] 代码实现符合需求描述
- [ ] 边界条件已处理（空数据、超大输入等）
- [ ] 错误处理完善（try-catch、错误提示）
- [ ] 没有遗留的调试代码（console.log、debugger）

### 浏览器兼容性
- [ ] 已在 Chrome 测试通过
- [ ] 已在 Safari 测试通过
- [ ] 没有使用 ES2020+ 新语法（?. ?? #private）
- [ ] 没有使用不兼容的 CSS 属性

### 代码质量
- [ ] 变量命名清晰、有意义
- [ ] 函数长度不超过 50 行
- [ ] 没有魔法数字（使用常量）
- [ ] 复杂逻辑有注释说明
- [ ] 没有重复代码（DRY 原则）

### 安全性
- [ ] 没有硬编码敏感信息（API Key、密码）
- [ ] 用户输入已转义（防 XSS）
- [ ] 没有暴露内部实现细节

### 性能
- [ ] 大数据量有分页或虚拟列表
- [ ] 事件处理有防抖/节流
- [ ] 没有内存泄漏（事件监听正确移除）

---

## 审查者检查清单

### 架构层面
- [ ] 代码位置正确（放在合适的模块）
- [ ] 没有破坏现有架构
- [ ] 接口设计合理（参数、返回值）

### 可维护性
- [ ] 代码易于理解
- [ ] 有适当的单元测试
- [ ] 文档已更新

### 团队规范
- [ ] 符合 ESLint 规则
- [ ] 符合命名规范
- [ ] 提交信息清晰

---

## 常见问题标记

| 标记 | 含义 | 示例 |
|------|------|------|
| [NIT] | 小问题，非阻塞 | "[NIT] 变量名可以更清晰" |
| [Q] | 疑问 | "[Q] 这里为什么用 var 不用 let?" |
| [BLOCKER] | 阻塞问题，必须修复 | "[BLOCKER] 有 XSS 漏洞" |
| [SUGGESTION] | 建议 | "[SUGGESTION] 可以提取为公共函数" |

---

## 审查流程

```
开发者提交 PR
    ↓
自动化检查 (ESLint)
    ↓
审查者审查 (使用本清单)
    ↓
   ├─ 通过 → 合并
   └─ 需修改 → 开发者修复 → 重新审查
```

## 快速参考

### 命名规范
```javascript
// 变量 - 驼峰
let studentList;
let currentPage;

// 常量 - 全大写下划线
const MAX_RETRY_COUNT = 3;
const API_BASE_URL = '/api/v1';

// 函数 - 动词开头
function getStudentById() { }
function renderStudentList() { }

// 布尔值 - is/has/should 开头
let isLoading;
let hasError;
let shouldRefresh;
```
