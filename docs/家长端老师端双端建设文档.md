# 家长端 / 老师端双端建设文档

> **覆盖时间**：从"加入家长端/老师端角色区分"开始，至今。
> **状态**：MVP 可演示。生产部署还差钉钉应用注册 + 真实学生数据接入 + HTTPS。
> **角色收敛**：当前只有 3 种角色 / 2 个端口（老师端 = 总务 + 班主任，家长端 = 家长）。

## 2. 角色矩阵（最终 = 3 种角色 / 2 个端口）

| 端口 | 角色 | role | sub_role | 5 个岛上看到什么 | 健康岛专属能力 |
|------|------|------|---------|-----------------|---------------|
| 🏫 **老师端** | 总务老师 | `teacher` | `general` | 全部学生 / 全部奖项 / 全校 AB 餐统计 | **上传两周菜单图** + **看各年级 AB 餐汇总** |

## 3. 后端变化

### 3.1 新增 / 修改的表

#### `user_bindings`（用户 → 角色绑定表）
```sql
CREATE TABLE user_bindings(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  dingtalk_unionid TEXT UNIQUE,
  role TEXT NOT NULL DEFAULT 'teacher',   -- teacher | parent
  sub_role TEXT,                          -- 仅 teacher：general | class
  bound_id_card TEXT,                     -- 家长用：自己孩子的学籍号
  bound_grade TEXT,                       -- 班主任用：本班年级
  bound_class TEXT,                       -- 班主任用：本班 class_name
  bound_name TEXT,
  created_at TEXT DEFAULT CURRENT_TIMESTAMP
);
```
> 支持旧库自动 `ALTER TABLE` 补列。

#### `weekly_menus`（总务老师上传的周菜单）
```sql
CREATE TABLE weekly_menus(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  week_number INTEGER NOT NULL,
  parity TEXT CHECK(parity IN ('odd','even')),
  date_start TEXT,
  date_end TEXT,
  image_path TEXT,           -- 相对 assets/menu-uploads/xxx.jpg
  notes TEXT,
  uploaded_by TEXT,          -- dt:unionId / ip:xxx
  created_at TEXT DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(week_number, parity)
);
```
> 同周次同奇偶重复上传 → 自动覆盖，旧图片自动清理。

#### `meal_choices`（家长 10 天选餐记录）
```sql
CREATE TABLE meal_choices(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  id_card TEXT NOT NULL,
  name TEXT,
  grade_name TEXT,
  class_name TEXT,
  week_number INTEGER NOT NULL,
  parity TEXT CHECK(parity IN ('odd','even')),
  weekday INTEGER CHECK(weekday BETWEEN 1 AND 5),   -- 1=周一..5=周五
  choice TEXT CHECK(choice IN ('A','B')),
  chosen_by TEXT,
  created_at TEXT DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(id_card, week_number, parity, weekday) ON CONFLICT REPLACE
);
CREATE INDEX idx_meal_choices_week  ON meal_choices(week_number, parity);
CREATE INDEX idx_meal_choices_class ON meal_choices(grade_name, class_name);
```
> 同学生同天再次选餐 → 覆盖旧记录，永远只有最新的一份。

#### `assets/menu-uploads/` 目录
上传的菜单图存储位置，访问路径 `/assets/menu-uploads/menu_w13_odd_1748340000.jpg`。

### 3.2 新增的 API 端点

| 方法 | 路径 | 谁能调 | 作用 |
|------|------|--------|------|
| GET | `/api/auth/me` | 所有人 | 返回当前角色 / 子角色 / 绑定 |
| POST | `/api/auth/bind` | （仅 CLI / 后台调）| 把钉钉 unionId 绑定到学生 / 班级 / 子角色 |
| GET | `/api/menus?week=N` | 所有人 | 列周菜单（家长选餐 / 老师查看） |
| POST | `/api/menus/upload` | 总务老师 | 上传菜单（multipart: image + week + parity + 日期） |
| POST | `/api/meal-choices` | 家长（限本人孩子） | 一次性提交 10 天选择 |
| GET | `/api/meal-choices/student/<id_card>` | 家长本人 / 老师 | 学生选餐历史 |
| GET | `/api/meal-stats/grade?week=N` | 老师 | 各年级 5 天 A/B 人数汇总（奇 + 偶） |
| GET | `/api/meal-stats/class?grade=&class=` | 班主任 / 总务 | 本班学生 × 10 天 A/B 明细 |

### 3.3 已有端点的访问控制改造

- `GET /api/students` — 家长只返回自己孩子那一条；老师看全部
- `GET /api/students/<id_card>` — 家长仅能查自己孩子；调 `_require_can_see` 鉴权
- `GET /api/fitness?id_card=X` — 家长强制锁定到 bound id_card

### 3.4 工具函数

| 函数 | 作用 |
|------|------|
| `_current_user()` | 返回 `{role, sub_role, bound_id_card, bound_grade, bound_class, identity}`；从 URL 参数 / Bearer token / IP 推断 |
| `_require_can_see(id_card)` | 家长仅能看自己孩子；老师通行 |
| `_lookup_binding(unionId)` | 从 `user_bindings` 表反查绑定 |
| `_ensure_user_bindings_table()` | 启动时建表 / 兼容旧库 |
| `_ensure_meal_tables()` | 启动时建表 |

## 4. 前端变化

### 4.1 新文件

#### `assets/user-auth.js` ✨ 新建
- 维护全局 `STATE`：`role / subRole / boundIdx / boundStudent / boundGrade / boundClass`
- 三层身份解析：URL demo > sessionStorage 缓存 > `/api/auth/me`
- 公开方法：
  - `UserAuth.ready(cb)` — 异步等身份就位
  - `UserAuth.getRole() / getSubRole()`
  - `UserAuth.isTeacher() / isParent() / isGeneralTeacher() / isClassTeacher()`
  - `UserAuth.getBoundStudent() / getBoundGrade() / getBoundClass()`
- DOM 自动切换 `_applyRoleDom()`：
  - `data-show-for / data-hide-for` 按 role
  - `data-show-sub / data-hide-sub` 按 sub_role
  - `data-text-teacher / data-text-parent` 自动覆盖 textContent
  - `data-html-teacher / data-html-parent` 自动覆盖 innerHTML
  - 顶栏自动注入角色徽章（家长 / 班主任 / 总务）

#### `assets/dingtalk-bootstrap.js` ✨ 新建
- 检测钉钉 WebView UA 后自动 SSO
- 拿 authCode → POST `/api/auth/dingtalk` → 拿 sessionToken 存 `sessionStorage.bs_session_token`

### 4.2 修改的文件

#### `assets/student-roster.js`
- 加 `_isParentLocked()` — 家长模式下 `attachPicker` 变只读，pill 上加 "🔒 我的孩子"
- `getCurrentIdx()` 家长强制返 bound idx；`setCurrentIdx()` 家长账号下静默忽略
- 自定义学生 CRUD 不受影响（家长不会触发，按 owner 隔离）

#### `assets/ai-helper.js`
- 默认走后端代理 `/api/ai/chat`；失败时如有本地 Key 自动降级直连
- 前端代码中**不再持有任何 API Key**

#### 5 个 HTML 页面（archive / health / reading / activity / homepage）
全部新增：
1. `<script src="assets/user-auth.js"></script>` 在 `student-roster.js` 之前加载
2. Banner / 副标题 / 按钮加 `data-text-teacher` / `data-text-parent` 双语切换
3. 家长不该看到的元素加 `data-hide-for="parent"`
4. 家长专属元素加 `data-show-for="parent"`

#### `island-health.html`（健康岛重点改造）
新增 4 个面板，按 role + sub_role 动态显示：

```html
<!-- 家长 -->
<div data-show-for="parent" id="parent-meal-panel">
  · 奇数周 / 偶数周 周次输入

<!-- 总务老师 -->

  · 第一周菜单上传卡（周次/起始/结束/图片 + 上传按钮）
```

- 启动时 `UserAuth.ready(...)` 路由到对应渲染函数

## 8. 关键决策记录

| 时间 | 决策 | 原因 |
|------|------|------|
| 初期 | 把当前页面直接作老师端 | 用户明确说"现在这个可以直接作为老师端" |
| 初期 | 家长身份用 sessionStorage 而非 localStorage | "关闭重开还是要更新到这个初始的，同一个 session 里保持同样的一个用户" |
| 中期 | 用 URL 参数 + sessionToken 双通道支持身份 | demo 演示无需后端，钉钉环境又能 SSO |
| 中期 | 文案 / 按钮用 `data-text-*` 声明式切换而非 JS 逻辑 | 每页少写代码、可读性高 |
| 后期 | 选餐 schema 用 `(id_card, week, parity, weekday)` 唯一约束 | 重复提交自动覆盖，无需先 DELETE |
| 后期 | 老师子角色用 `sub_role` 而非新增 `general_teacher` / `class_teacher` 角色 | 共用 role 系统的权限/UI 切换，复用性高 |
| 终期 | **角色收敛为 3 种 / 2 个端口**，移除 `admin` 这个 UI 角色 | 用户明确"目前我们只需要三种角色"；管理动作改成走 CLI（`manage_bindings.py`）+ 服务端命令，避免维护多一套后台 |
| 终期 | 钉钉 unionId ↔ 学生 / 班级 的绑定改成 CLI + CSV 批量导入 | 学校往往一次性导入 → 后台 UI 维护成本太高，不如让管理员跑一条命令 |

## 9. 后续接入钉钉的最小步骤

1. **钉钉开放平台** → 创建 H5 微应用 → 拿 `AgentId / AppKey / AppSecret / CorpId`
2. **填 `server/.env`**：
   ```
   BAIDU_AI_KEY=bce-v3/ALTAK-xxxxxxxxxxxxxxxx（已脱敏）
   DINGTALK_AGENT_ID=...
   DINGTALK_APP_KEY=...
   DINGTALK_APP_SECRET=...
   DINGTALK_CORP_ID=...
   SESSION_SECRET=<随机长串>
   ```
3. **HTTPS 部署**（钉钉强制）：参考 `server/README.md` 的 Nginx + Gunicorn 方案
4. **首页 `<head>` 加 3 行**：
   ```html
   <script>window.BS_DINGTALK_CORP_ID = '你的CorpId';</script>
   <script src="//g.alicdn.com/dingding/dingtalk-jsapi/2.13.42/dingtalk.open.js"></script>
   <script src="assets/dingtalk-bootstrap.js"></script>
   ```
5. **批量录入用户绑定**：让学校提供两份 CSV，按文档第 10 节格式
   ```bash
   python3 server/manage_bindings.py import-parents parents.csv
   python3 server/manage_bindings.py import-class-teachers class-teachers.csv
   python3 server/manage_bindings.py add-teacher-general <总务unionId> 张总务
   python3 server/manage_bindings.py list   # 检查
   ```
6. **完成** — 各角色用户用钉钉打开应用 → 自动 SSO → 看到自己那一份

## 10. CLI 绑定工具速查（`server/manage_bindings.py`）

```bash
# 查看现有绑定
python3 server/manage_bindings.py list

# 单条绑定
python3 server/manage_bindings.py add-parent          <unionId> <学籍号>  [姓名]
python3 server/manage_bindings.py add-teacher-class   <unionId> <年级> <班级> [姓名]
python3 server/manage_bindings.py add-teacher-general <unionId> [姓名]

# CSV 批量
python3 server/manage_bindings.py import-parents          parents.csv
python3 server/manage_bindings.py import-class-teachers   class-teachers.csv

# 删除单个
python3 server/manage_bindings.py del <unionId>

# 清空（危险，需 --yes）
python3 server/manage_bindings.py clear --yes
```

**班主任 CSV** (`class-teachers.csv`)：
```csv
unionId,grade,class,bound_name

wwwwwwwwwwwwwww,四年级,2班,四(2)班 李老师
```
