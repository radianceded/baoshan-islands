## 1. 文档目的

本文档用于说明本次新增的 **AI 营养配餐 / AB 餐选餐** 与 **社团兴趣课报名** 两项功能，包括使用流程、角色权限、数据同步方式、部署方法、验收结果和上线边界。

本次交付遵循“保留原站其他功能，只增加两项业务能力”的范围约束。未在本文列出的原有岛屿功能，不属于本次新增功能的验收范围。

## 2. 交付范围

### 2.1 已交付功能

1. 三身份登录入口：总务老师、班主任老师、学生家长。
2. 总务老师菜单图片与 XLSX 上传、解析、在线修正、确认发布。
3. 总务老师查看全校各年级、单双周、每日 A/B 餐人数统计。
4. 班主任查看本班学生逐人、逐日选餐明细和班级汇总。
5. 家长查看菜单图片、菜单文字和孩子的 AI 营养建议。
6. 家长完成连续两周共 10 个供餐日的 A/B 餐选择。
7. 选餐截止时间控制；截止前可重新提交，以最后一次提交为准，截止后禁止修改。
8. 总务老师维护社团、容量和上下架状态，并查看每个社团报名名单。
9. 班主任查看本班所有学生的社团报名情况。
10. 家长为绑定孩子报名社团、查看“我已报名”并取消报名。
11. 社团容量、重复报名、并发超卖、上课时间冲突和每名学生最多一门社团的服务端校验。

### 2.2 本次未包含

- 钉钉生产应用参数和真实组织身份配置。
- 三校区学生数据库物理拆分。
- 多张菜单图片一次上传；当前一份周菜单对应一张图片。
- 营养建议的医学诊断或治疗用途。
- 对原站全部历史功能的重构。

## 3. 系统结构

```text
浏览器 / 钉钉 H5
       │
       ├── 静态页面：HTML、CSS、JavaScript
       │
       └── /api/*
              │
              ▼
         Flask 后端
              │
              ├── SQLite：student_data.db
              ├── 菜单文件：assets/menu-uploads/
              └── AI 服务：DeepSeek 或百度千帆（由环境变量配置）
```

当前前后端由同一 Flask 应用提供，浏览器通过 Bearer Session Token 调用后端。菜单发布、选餐、社团报名及角色权限均由后端校验，不能只依赖前端隐藏按钮。

## 5. 营养配餐与 AB 餐业务流程

### 5.1 总务老师发布菜单

1. 使用总务老师入口登录。
2. 打开健康岛，系统直接进入营养配餐统计页面。
3. 选择周次、单双周类型、开始日期、结束日期和家长选餐截止时间。
4. 上传一张菜单图片和一份 `.xlsx` 菜单文件。
5. 点击“解析菜单”。此时只生成草稿，班主任和家长不可见。
6. 在解析结果中直接修改菜名、营养数值或日期，无需返回修改 XLSX。
7. 系统重新检查阻断错误和提醒项。
8. 点击“确认发布”。发布成功后，菜单、图片和结构化餐食数据同时生效。

只有“确认发布”会产生对其他身份可见的数据。未发布草稿不会污染正式菜单。

### 5.2 班主任查看班级数据

1. 使用班主任入口登录。
2. 打开健康岛，系统直接进入本班营养配餐页面。
3. 查看总务老师发布的菜单图片和餐食文字信息。
4. 查看选定连续两周内每日 A 餐、B 餐人数。
5. 查看每一名学生每天选择的 A 餐或 B 餐，以及 10 天完成情况。

班主任不能上传菜单，也不能替学生修改选餐。班级和年级由账号绑定关系决定，不能通过修改页面参数越权查看其他班级。

### 5.3 家长查看建议并选餐

1. 使用学生家长入口登录。
2. 打开健康岛中的“AI 营养配餐”。
3. 页面只读取当前账号绑定孩子的档案、过敏信息、菜单和推荐结果。
4. 家长可通过“配餐”和“选餐”视觉锚点快速定位对应区域。
5. 查看每日 A/B 餐文字信息、图片、营养数据和 AI 推荐理由。
6. 完成奇数周与偶数周共 10 个供餐日的 A/B 餐选择。
7. 截止时间前可重新提交，数据库以最后一次完整提交为准。
8. 截止时间后，前端和后端均禁止修改。

家长不能查看其他孩子、全班或全校数据，也不能执行批量推荐、导出全体结果或替其他学生确认。

### 5.4 数据同步机制

系统没有把菜单分别复制到三个身份页面。总务老师、班主任和家长读取的是同一数据库中的已发布菜单：

```text
总务老师解析并确认发布
          │
          ▼
     已发布周菜单
       ├── 班主任读取：菜单 + 本班统计 + 学生逐日明细
       └── 家长读取：菜单 + 自己孩子建议 + 自己孩子选餐
```

因此，“同步”在确认发布后即时生效，页面刷新或重新进入即可看到，不需要人工导出再导入。若总务老师只完成解析但没有点击“确认发布”，其他身份不会看到草稿。

## 6. 社团兴趣课业务流程

### 6.1 总务老师

- 新增社团课程。
- 修改课程基础信息和人数上限。
- 上架或下架课程。
- 查看每个社团当前人数及学生名单。
- 人数上限不得低于当前已报名人数。

### 6.2 班主任

- 只查看账号绑定班级的学生。
- 查看班内每名学生已报名的社团。
- 不替家长报名或取消，不维护社团和容量。

### 6.3 学生家长

- 浏览可报名社团并查看是否满员。
- 每名学生最多报名一门社团。
- 服务端检查重复报名、课程容量和上课时间冲突。
- 报名成功后在“我已报名”区域查看。
- 可在“我已报名”区域取消当前报名。

报名和取消均只作用于当前账号绑定的孩子。并发请求通过事务和数据库校验防止重复占位或超过课程容量。

## 7. 数据与文件

### 7.1 主要持久化内容

- 主数据库：`student_data.db`
- 菜单上传文件：`assets/menu-uploads/`
- 运行配置：`server/.env`
- 运行日志：`logs/`

部署、迁移和回滚时，必须同时保护数据库与菜单上传目录。只替换代码而遗漏这两项，会造成选餐记录或菜单图片丢失。

### 7.2 菜单数据原则

- XLSX 是菜单文字和营养字段的结构化来源。
- 图片用于家长和老师核对原始菜单。
- 当前每个周菜单批次上传一张图片。
- 周次、单双周、日期范围和截止时间由总务老师填写并在发布前校验。
- 已发布菜单才参与家长选餐、班级统计和 AI 推荐展示。

### 7.3 生产数据接入要求

上线前应使用学校提供的学生、教师、家长孩子绑定和账号绑定数据做一次完整导入演练，重点核对：

- 学生唯一编号在各表中一致且长期稳定。
- 校区、年级、班级字段采用统一枚举和格式。
- 班主任账号只绑定一个明确班级。
- 家长账号只访问有效绑定的孩子。
- 姓名、身份证件等敏感字段遵守最小化使用和脱敏要求。

## 8. 本地部署与演示

### 8.1 环境要求

- Python 3.11
- 依赖：Flask、Flask-CORS、openpyxl
- 推荐浏览器：Chrome 或 Edge 80 以上

### 8.2 初始化演示数据

在项目根目录执行：

```powershell
python server/manage_accounts.py seed-demo
```

### 8.3 启动服务

必须从项目根目录启动，不能进入 `server/` 后直接启动，否则可能找不到 `nutrition` 模块。

```powershell
$env:PORT='5051'
python -m server.app
```

访问：

```text
http://127.0.0.1:5051/login.html
```

## 9. 生产部署建议

推荐使用 Nginx + Gunicorn + systemd，并从项目根目录加载 `server.app:app`：

```bash
cd /srv/baoshan/current
env PYTHONPATH=/srv/baoshan/current \
    DISABLE_DEMO=1 \
    /path/to/venv/bin/gunicorn \
    --bind 127.0.0.1:5000 \
    --timeout 30 \
    --workers 1 \
    server.app:app
```

SQLite 写入场景下，当前建议先使用一个 Gunicorn worker。若后续需要多实例或更高并发，应先迁移到独立数据库服务并验证事务行为。

生产环境至少配置：

```ini
SESSION_SECRET=<64位以上随机密钥>
DISABLE_DEMO=1
DEBUG=0
CORS_ORIGINS=https://正式域名
DEEPSEEK_API_KEY=<可选，按实际AI供应商配置>
DEEPSEEK_AI_MODEL=<模型名>
DINGTALK_AGENT_ID=<待配置>
DINGTALK_APP_KEY=<待配置>
DINGTALK_APP_SECRET=<待配置>
DINGTALK_CORP_ID=<待配置>
```

发布前应先备份：

```text
student_data.db
assets/menu-uploads/
server/.env
```

## 11. 已知边界与上线前置条件

当前版本可作为本地 Demo、测试环境和受控试点候选版本使用；正式面向全校上线前仍需完成：

1. 将本地集成提交合并到远端正式分支，并以固定提交号制作 Release。
2. 在预发布环境使用真实数据副本完成导入与权限抽查。
3. 配置钉钉生产身份与家长孩子绑定，关闭全部 Demo 身份旁路。
4. 对原站其他岛屿功能执行回归，确认新增代码没有影响历史页面。
5. 配置 HTTPS、数据库及菜单文件备份、日志轮转和监控告警。
6. 制定菜单误发布、选餐统计异常和社团名额异常的人工处理流程。
7. 明确 AI 营养建议仅作辅助参考，不替代营养师或医生的专业判断。

在以上事项完成并通过验收前，不建议将当前版本描述为成熟的全校生产后端系统。
