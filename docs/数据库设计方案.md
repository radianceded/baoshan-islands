## 1. 你提出的设计想法 vs 现状

### 你想要的架构
```
┌─────────────────────┐
│ 用户登录表（老师/家长）│  ← 账号密码 / 钉钉 unionId → 角色 + 绑定
└──────────┬──────────┘
           ▼
┌─────────────────────┐
│   学生档案大表       │  ← 学生主数据（一行一个学生）
└──────────┬──────────┘
           ▼
    ┌──────┴──────┬──────────┬──────────┬──────────┐
    ▼             ▼          ▼          ▼          ▼
┌────────┐  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
│健康岛   │  │成就岛   │ │活动岛   │ │阅读岛   │ │选餐    │
│体测/餐  │  │奖项/证书│ │社团     │ │借阅     │ │meal    │
└────────┘  └────────┘ └────────┘ └────────┘ └────────┘
```

### 现状（9 张表 × 一些零散数据）
| 表名 | 行数 | 性质 | 评价 |
|------|------|------|------|
| `students` | 45 | 主表 | ✅ 学生大表，符合设计 |
| `fitness_tests` | 130 | 子表（健康） | ✅ 体测 |
| `vision_tests` | 0 | 子表（健康） | ✅ 视力档案 |
| `allergies` | 0 | 子表（健康） | ✅ 过敏 |
| `awards` | 320 | 子表（成就） | ✅ 奖项 |
| `clubs` | 674 | 子表（活动） | ✅ 社团报名 |
| `ab_menus` | 1893 | 独立 | ⚠️ AB 餐**菜单**（属于校园配置，不算学生数据） |
| `user_bindings` | 0 | 主表 | ✅ 钉钉账号绑定（但当前 demo 用 hardcoded 账户）|
| `sqlite_sequence` | 5 | 系统 | 自动维护 |

**结论**：架构和你想的基本一致，**5 张子表已经按岛屿拆开**了。问题主要在：
1. **用户登录表** 现在是 hardcoded Python 字典，**还没用 `user_bindings`**
2. **菜单上传 / 选餐** 是新加的，对应 `weekly_menus` / `meal_choices`（已建但还没存数据）
3. **证书** 现在是 JSON 文件 `assets/cert_awards.json` + 图片在 `assets/award-certs/`，**没进数据库**
4. **阅读** 目前是纯前端 mock，**还没建表**

## 2. 完整规划

### 2.1 用户表（待整理）

```sql
-- 现有：user_bindings（钉钉模式）
-- 待补：accounts（账号密码模式，过渡到钉钉前的演示 + 兜底）
CREATE TABLE accounts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  role TEXT NOT NULL,                  -- teacher | parent
  sub_role TEXT,                       -- general | class
  bound_id_card TEXT,                  -- 家长：孩子学籍号 → students.id_card
  bound_grade TEXT,                    -- 班主任：年级
  bound_class TEXT,                    -- 班主任：班级
  display_name TEXT,
  dingtalk_unionid TEXT,               -- 关联钉钉 SSO 后填这个
  created_at TEXT DEFAULT CURRENT_TIMESTAMP
);
CREATE UNIQUE INDEX idx_accounts_dingtalk ON accounts(dingtalk_unionid) WHERE dingtalk_unionid IS NOT NULL;
```

> 跟 `user_bindings` 合并 / 替换。当前的 hardcoded `DEMO_ACCOUNTS` 字典迁进来。

### 2.4 详细 schema

#### 健康岛 · 选餐相关
```sql
-- 周菜单（总务老师上传）— 已建好
weekly_menus (id, week_number, parity, date_start, date_end, image_path, notes, uploaded_by, created_at)

-- 学生选餐 — 已建好
meal_choices (id, id_card, name, grade_name, class_name, week_number, parity, weekday, choice, chosen_by, created_at)

-- 旧菜单表 ab_menus 跟 weekly_menus 重叠，建议：
-- 方案 A：保留 ab_menus 作为历史只读，新流程只用 weekly_menus
-- 方案 B：迁移 ab_menus → weekly_menus + 加 dishes_json 字段
ALTER TABLE weekly_menus ADD COLUMN dishes_json TEXT;  -- 存 A/B 餐每天的菜品名（来自旧 ab_menus）
```

#### 成就岛 · 证书入库
```sql
CREATE TABLE award_certs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  student_id_card TEXT,                -- 不一定能 join 上 students（真实证书学生可能不在 45 名 demo 里）
  student_name TEXT NOT NULL,          -- 显示用
  grade TEXT NOT NULL,                 -- 如 "三年级"
  class_name TEXT NOT NULL,            -- 如 "三（1）"
  competition TEXT,
  prize TEXT,
  subject TEXT,
  teacher TEXT,
  image_path TEXT NOT NULL,            -- assets/award-certs/...
  source TEXT,                         -- 'cert-scan-2026' 等
  uploaded_at TEXT DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_award_certs_name ON award_certs(student_name);
CREATE INDEX idx_award_certs_class ON award_certs(grade, class_name);
```

> 用一个 `python3 server/import_certs.py --to-db` 命令把现有 JSON 一次性灌进去。

#### 阅读岛
```sql
CREATE TABLE books (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  title TEXT NOT NULL,
  author TEXT,
  isbn TEXT,
  cover_color TEXT,
  tags TEXT,                            -- 逗号分隔 '科幻,冒险'
  desc TEXT,
  cover_path TEXT,
  in_stock INTEGER DEFAULT 1
);

CREATE TABLE borrows (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  id_card TEXT NOT NULL,                -- → students.id_card
  book_id INTEGER NOT NULL,             -- → books.id
  borrow_date TEXT,
  due_date TEXT,
  return_date TEXT,
  status TEXT CHECK(status IN ('borrowing','returned','overdue')) DEFAULT 'borrowing'
);
CREATE INDEX idx_borrows_student ON borrows(id_card);
```

#### 活动岛
```sql
-- 现有 clubs 是社团本身。加一张 signup 表追踪学生报名
CREATE TABLE club_signups (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  id_card TEXT NOT NULL,
  club_name TEXT NOT NULL,
  semester TEXT,
  status TEXT DEFAULT 'signed',
  created_at TEXT DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(id_card, club_name, semester)
);
```

## 3. 数据流（家长视角）

```
   家长用账号 parent_chen_silin 登录
            ↓
       POST /api/login
            ↓
   accounts → role=parent, bound_id_card=G310...
            ↓
       前端拿到身份，跳到 island-homepage.html
            ↓
   点击"📚 档案岛"
            ↓
   GET /api/students?role=parent
   ← 后端按 bound_id_card 过滤，只返 1 条
            ↓
   档案岛家长视图渲染该学生
   ├─ fitness_tests 体测
   ├─ allergies 过敏
   ├─ awards + award_certs 奖项 / 证书
   ├─ borrows → books 借阅
   └─ club_signups 社团
```
